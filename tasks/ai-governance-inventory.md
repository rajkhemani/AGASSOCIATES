## Executive Summary

The AGASSOCIATES monorepo operates **three distinct AI execution pipelines** with **no shared governance infrastructure**:

| Pipeline | Subsystem | LLM Provider | Model | Purpose |
|----------|-----------|--------------|-------|---------|
| **LangGraph Document Pipeline** | `ag-associates-ai/backend/agents.py` | vLLM (local Qwen2.5-7B) / Groq (prod) | `qwen2.5-7b-instruct` / `llama-3.3-70b` | Rental agreement generation: Intake → Draft → Audit |
| **Conversational Multi-Agent System** | `ag-associates-ai/backend/agents/` | vLLM (local Qwen2.5-7B) | `qwen2.5-7b-instruct` | 7 specialist agents (Auditor, Vyasa, Bouncer, Accountant, NOI, Executor, Drafter) |
| **Multi-Modal Processors** | `ag-associates-ai/backend/media/` | Whisper / Gemini 2.0 Flash / vLLM Vision | Various | Audio→text, Image→text, PDF/Excel/DOCX extraction |
| **Gemini AI Endpoints** | `ag-platform/src/server/aiRouter.ts` | Google Gemini | `gemini-3.1-pro-preview` / `text-embedding-004` | 7 REST endpoints (brief, tasks, email, invoice, summarize, search, vet) |
| **Hierarchical Coordinator** | `ag-platform/services/coordinator/` | Google Gemini | `gemini-2.0-flash-exp` | 4 specialist roles (research, code, writer, reviewer) via worker threads |

**Critical Finding:** None of these pipelines share provenance tracking, model routing, prompt versioning, or evidence storage. Each operates in isolation with ad-hoc logging.

## 1. LangGraph Document Pipeline (`ag-associates-ai/backend/agents.py`)

### Architecture
```
Aisha (Intake) → Guardrail → Bouncer → Drafter (RAG + Template) → Auditor (QA Loop)
                                    ↓
                              should_revise(): score < 85 → back to Drafter (max 3 revisions)
```

### State Tracking (`AgentState` TypedDict)
```python
# Input
raw_input, sender, org_id
# Extracted by Aisha
tenant_name, landlord_name, rent_amount, property_address, agreement_start_date,
agreement_duration, security_deposit, stamp_duty_paid, extracted_json
# Generated by Drafter
template_id, template_content, drafted_document, pdf_path
# Guardrail/Bouncer
guardrail_passed, bouncer_passed, bouncer_feedback
# Audit
audit_passed, audit_feedback, revision_count
# Metadata
current_node, errors[], timestamps{}
```

### Provenance Mechanisms
| Mechanism | Coverage | Gaps |
|-----------|----------|------|
| **LangSmith `@traceable`** | Each node decorated (`Aisha_Intake_Agent`, `Guardrail_Regex_Validator`, `Bouncer_Math_Validator`, `Auditor`) | Optional — requires `LANGSMITH_API_KEY`; not confirmed in prod |
| **`workforce.ledger.record_activity()`** | Called at each node with `capability_code` (e.g., `case.intake`, `case.validate`, `case.draft`, `case.audit`) | Payload is free-form JSON; no structured schema for model, prompt, tokens |
| **State timestamps** | `timestamps.{node}_start/end` for each node | In-memory only; not persisted to DB |
| **Revision tracking** | `revision_count` increments on each Drafter→Auditor loop | No history of prior drafts; only final `drafted_document` kept |

## 11. Conclusion

The AGASSOCIATES repository operates **five distinct AI execution pathways** with **zero shared governance infrastructure**. Each pipeline has ad-hoc logging (`record_activity`, `staff_activity`, `audit_trail`) but lacks:

1. **Persistent AI run registry** (`ai_runs`)
2. **Document versioning** (`document_versions`)
3. **Prompt versioning** (`prompt_versions`)
4. **Model routing audit** (`model_routes`)
5. **Structured evidence/confidence/risk storage** (`evidence_store`, `confidence_scores`, `risk_flags`)

The **frozen architecture requirements (P2, P2-B, P3)** mandate these governance tables and cross-system trace correlation. Implementation should start with the `ai_runs` table as the foundational provenance anchor, instrumenting `record_activity()` to populate it from all five pipelines.

**Estimated effort for P2 compliance:** 3-5 days (schema + instrumentation + migration)
**Estimated effort for P2-B compliance:** 5-7 days (prompt registry + model routing + confidence framework)
**Estimated effort for P3 compliance:** 10-15 days (dashboard + A/B testing + compliance reports)
